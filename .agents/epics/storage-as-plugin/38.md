## Technical Details

**File: `docs/adrs/0017-storage-plugin-system.md`**

Follow the same format as ADR 0016 (frontmatter with status/date/deciders, then sections).

Key points to cover:
- **Context**: ADR 0016 established CDN-loaded plugins for monitoring (Sentry, PostHog). ADR 0005 established two storage backends with boot-time context detection in the host. This ADR extends the plugin system to cover storage, making it consistent and composable.
- **Decision**: Introduce `PluginType` and `AlistigoStorageExtension`. Storage plugins (claude-storage-plugin, local-storage-plugin) follow the same CDN-loaded, independently-versioned pattern. Host injects defaults; priority = insertion order; in-memory fallback.
- **Rationale**: Consistency with ADR 0016's model; extensibility (custom storage backends without touching host); testability (storage plugin = unit-testable object); no rebuild needed to swap storage.
- **Consequences**: `App.tsx` decoupled from storage implementations; storage selection failure is graceful (in-memory fallback); a CDN outage affecting storage plugins results in in-memory-only operation, not a crash.
