# Task: User Plugin → Actors Section Bridge

## Description

Wire the user plugin's `user:changed` event to populate the `alistigo:actors` section of the list document. The artifact-list host maintains a local `actorsById` map and passes it to the serializer on every save.

## Acceptance Criteria
- [ ] The artifact-list host subscribes to the `user:changed` plugin event after plugin setup
- [ ] On `user:changed`, the host updates a local `actorsById: Map<string, AlistigoActorRecord>` keyed by actorId
- [ ] The actorId used as the map key is the same actorId used when issuing list commands (the current user's actor identity)
- [ ] `ListDocumentSerializer.serialize()` is called with the `actorsById` map as part of `SerializeOptions`
- [ ] On plugin setup (when the user is first loaded from storage), the actor is registered immediately without waiting for a user change
- [ ] If no user plugin is active, the actors map is empty and no `alistigo:actors` section is written

## Technical Details

**Find:** The artifact-list host's main app file (likely `packages/artifact-list/src/App.tsx` or similar). Understand how: (a) the plugin runtime is initialized, (b) `user:changed` can be subscribed, (c) commands are issued with actorId, (d) documents are serialized.

**How actorId is determined:** The list domain's `ActorId` for the current user is derived from the user plugin's `User.id`. The user plugin emits `{ userId, pseudo }` on `user:changed`. The actorId in the event log is what the host passes when issuing commands — it must match.

**Pattern to implement:**
```typescript
// In host setup, after plugin runtime is initialized:
let actorsById = new Map<string, AlistigoActorRecord>();

pluginRuntime.on("user:changed", ({ userId, pseudo }) => {
  // Build AlistigoActorRecord from available data
  // avatar must be retrieved from the user plugin context or the store
  const actorRecord: AlistigoActorRecord = {
    "alistigo:actorId": currentActorId, // same ID used in commands
    "alistigo:userId": userId,
    "alistigo:pseudo": pseudo,
    "alistigo:avatar": currentAvatar,   // from user plugin context
  };
  actorsById.set(actorRecord["alistigo:actorId"], actorRecord);
});
```

**Key challenge:** The avatar is not included in the `user:changed` event payload (currently just `{ userId, pseudo }`). Options:
1. Read it from `UserContext` (if accessible in the host) 
2. Extend the `user:changed` event payload to include `avatar`

Prefer option 2: extend `AlistigoPluginEventMap["user:changed"]` to include `avatar?: string`. This is additive — existing subscribers ignore the new field.

Update `packages/artifact-plugin-api/src/types.ts`:
```typescript
"user:changed": { userId: string; pseudo: string; avatar?: string };
```

And update the user plugin's `onUserChanged` emit to include `avatar`:
```typescript
ctx.emit("user:changed", { userId: u.id, pseudo: u.pseudo, avatar: u.avatar });
```
