# Task: Artifact-List Host Wiring

## Description

Wire everything together in the `artifact-list` host application. The checkbox plugin must be registered in the plugin runtime, `checkListElement` commands must be dispatched through the list aggregate, the `alistigo:plugins` section must be written to the document, and the `ListView` must receive `plugins`, `events`, and `onPluginCommand` props.

## Acceptance Criteria
- [ ] `checkboxPlugin` is imported from `@alistigo/artifact-checkbox-plugin` and added to the plugin list in `artifact-list`
- [ ] The `onPluginCommand` handler receives `("checkListElement", { elementId, checked })` and:
  1. Calls `createCheckListElementEvent(elementId, actorId, listId, checked)` to create the event record
  2. Appends this event to the list document's event log (how this is done depends on the existing host architecture — investigate)
  3. Updates `itemListElement[elementId]["alistigo:metadatas"]["checkbox"]["selected"]` in the document to the new value
  4. Persists the document to storage
- [ ] `ListView` is called with `plugins={[checkboxPlugin]}`, `events={document["alistigo:listEventLog"]}`, and `onPluginCommand`
- [ ] The document's `alistigo:plugins` section is written on initialization with the active plugin list
- [ ] `pnpm nx run artifact-list:build` passes
- [ ] `pnpm nx run artifact-list:typecheck` passes

## Technical Details

**Find:** The artifact-list host's main entry and state management. Look at:
- `packages/artifact-list/src/` — main app entry, state hooks, storage handling
- How `ListDocumentSerializer.serialize()` is called today
- How the `AlistigoProvider` / list aggregate is used

**Dispatch pattern:** The `checkListElement` command is NOT a list-domain command (the list aggregate doesn't know about checkbox). Instead:
- Create the `AlistigoListElementCheckedRecord` event directly using `createCheckListElementEvent()`
- The event is appended to the **document's event log** (without going through the domain aggregate)
- The denormalized state (`alistigo:metadatas`) is updated to reflect the new checked state
- The document is re-serialized and saved

This means maintaining the document state directly in the host (not only through the aggregate). The host already has a `previousDocument` concept in the serializer — extend this to also handle plugin events.

**Plugin registration:**
```typescript
// In artifact-list plugin registration array:
import checkboxPlugin from "@alistigo/artifact-checkbox-plugin";
// ... other plugins ...
const plugins = [storagePlugin, userPlugin, checkboxPlugin, /* ... */];
```

**`alistigo:plugins` section:** When the document is serialized, include the active domain-contribution plugins:
```typescript
// Add to SerializeOptions in task 002:
activePlugins?: AlistigoPluginRecord[];
```
Or write directly into the document before serialization.

**Prop drilling to ListView:** Find where `ListView` is rendered in the host (likely `AlistigoApp.tsx` or the main app component). Pass:
- `plugins={domainPlugins}` — only plugins that have `renderListElementLeading` or `reduce`
- `events={currentDocument["alistigo:listEventLog"]}`
- `onPluginCommand={handlePluginCommand}`
