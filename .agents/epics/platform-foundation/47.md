# Task 47: Make document-validator CLI generic

## Goal

Refactor the `document-validator` CLI (formerly `alistigo-document-validator`) to accept
a `--schema` argument pointing to any JSON Schema file or package. Default remains the
list document schema for backward compatibility.

## New API

```sh
# validate a list document (default, backward-compat)
document-validator my-list.json

# validate any artifact's document against its schema
document-validator my-artifact.json --schema ./path/to/schema.json
document-validator my-artifact.json --schema @alistigo/list-document-format
```

## Implementation notes

- Read current implementation in `cli/document-validator/` (after Task 46 rename)
- Add `--schema` CLI flag (use Clipanion, existing pattern)
- When `--schema` is a path: load JSON file directly
- When `--schema` is a package name: resolve via `require.resolve()` / dynamic import,
  look for a `schema.json` or `dist/schema.json` export
- When `--schema` is omitted: use `@alistigo/list-document-format` schema (default)
- Error clearly if schema cannot be resolved

## Acceptance criteria

- [ ] `document-validator <file>` works with no schema arg (defaults to list schema)
- [ ] `document-validator <file> --schema ./custom.schema.json` validates against custom schema
- [ ] Help text (`--help`) documents the `--schema` flag
- [ ] TypeScript types: no `any` without justification
- [ ] `pnpm build:typecheck` passes
- [ ] `pnpm qa:lint` passes
